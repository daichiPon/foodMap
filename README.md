# Food Map Webアプリ 開発・拡張設計書

React + TypeScript + Vite で作成した、現在地や登録地点を地図上で共有できるPWA（Webアプリ）です。
今後は「地図 × SNS × マッチング」の要素を強化し、親しい友人との共有や、ユーザー同士のインタラクション（いいね・タイムライン）がシームレスに行えるアプリへと発展させます。

---

## 1. アプリ概要・公開情報
- **公開URL**: https://food-map-lime.vercel.app
- **主要機能**: ログイン、店舗位置登録、地図ピン表示（現在地＆登録地点）、店舗検索（カテゴリー・金額・ユーザー単位）、HotPepperグルメAPI連携（周辺店舗取得）
- **注意書き**: iPhone等で初回ログイン時に位置情報が取得できない場合は、「設定 → 一般 → 転送またはiPhoneをリセット → 位置情報とプライバシーをリセット」を案内する。

## 2. 技術スタック
- **フロントエンド**: React, TypeScript, Vite (PWA)
- **バックエンド**: AWS Amplify (GraphQL API, Cognito認証, Lambda, DynamoDB, S3)
- **地図**: MapBox
- **外部API**: HotPepperグルメAPI
- **ホスティング**: Vercel

## 3. 今後の拡張要件（実装タスク）

### ① UI/UXの大幅刷新：固定フッターナビゲーションの導入
スマートフォンのネイティブアプリのような操作感を実現するため、画面下部に固定フッター（Bottom Navigation）を配置します。フッターには以下の4〜5つの導線を設置してください。

*   **[ホーム/マップ]**: メインの地図画面（現在地＆ピン表示）
*   **[タイムライン]**: 新設。「最近登録された店舗データ」がタイムライン形式（画像・レビュー・いいねボタン）でスクロール表示されるページ
*   **[新規登録]**: 新設。写真や位置情報をその場で素早く登録できるシンプルな専用登録ページ
*   **[フレンド共有]**: 新設。友人登録（フォロー）した特定のユーザーと、2人きりのクローズドな店舗データを地図・リストで共有するページ
*   **[マイページ]**: 自身の登録情報、いいね一覧、フレンド管理画面

### ② 「クイック登録」機能の強化
ユーザーが迷わず直感的に投稿できるよう、新規登録のUXを徹底的に簡素化します。
*   カメラ起動または写真選択（S3保存）を最上部に配置
*   「現在地から自動で位置情報を取得してセットする」ボタンの設置
*   店舗名、カテゴリー、金額、簡単レビューの入力項目

### ③ SNS・マッチング要素（いいね＆タイムライン）
*   **いいね機能**: 各店舗データに対して、他のユーザーが「いいね（ハート）」を押せる機能（DynamoDBにLikeテーブルまたはLocationへのカウント追加が必要）
*   **タイムライン表示**: 最近登録されたデータ順にソートして表示。マッチングアプリのカード風、またはInstagramのような縦スクロールUI。

### ④ 親しい友人との「2人だけの共有スペース」
*   **フレンド・パートナー紐付け**: ユーザーIDやQRコード等で特定の友人とペアリング（またはグループ化）する機能。
*   **限定共有モード**: マップやタイムライン上で、「全員の投稿」「自分のみ」「〇〇との共有データ」をタブやフィルターで切り替えられるようにする。

## 4. AIへの提案・追加おすすめ機能（検討事項）
Claude Codeは、以下の機能についてもUX向上のために積極的に提案・実装プランを立ててください。

1.  **AIによる「行ったお店」の自動要約（要検討）**
    *   ユーザーが登録した写真や短いコメントから、AIが自動でお店のキャッチコピー（例：「デートに最適！隠れ家イタリアン」など）を生成してタグ付けする機能。
2.  **マッチング度（相性診断）の可視化**
    *   フレンド登録したユーザーと、お互いに行ったお店の「カテゴリー（居酒屋、カフェ等）」や「価格帯」の重複度合いを計算し、「2人の食の相性：85%」のように表示する機能。
3.  **行きたいリスト（WANT機能）**
    *   友人が投稿した店やタイムラインで見つけた店を「行った（DONE）」だけでなく、「行ってみたい（WANT）」としてピン保存できる機能。2人の「行きたい」が一致したら通知するマッチングアプリ風演出。

## 5. 開発・バックエンド更新手順（チートシート）

### 開発の基本フロー
1. `git clone` 後、 `npm run dev` でローカルサーバー起動。

### DynamoDB/Amplifyのスキーマ変更手順
1. `data/resource.ts` と `amplify/api/schema.graphql` に新しいフィールドやテーブル（例: `Like`, `Friendship` など）を追加。
2. サンドボックス環境にデプロイ:
   ```bash
   npx ampx sandbox
   ```

### フロントエンドへの型・クエリ反映手順
1. グラフィカルクライアントコードの自動生成（`src/graphql/` や `src/models/` の更新）:
   ```bash
   npx ampx generate graphql-client-code
   ```
2. 必要に応じて `src/graphql/mutations.ts`, `queries.ts` に新フィールドを手動追記。
3. バックエンドの最新定義をフロントにコピー:
   ```bash
   copy amplify_outputs.json src/amplify_outputs.json
   ```
